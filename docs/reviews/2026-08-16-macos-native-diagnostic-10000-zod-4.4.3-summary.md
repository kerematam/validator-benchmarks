## Zod 4.4.3 outcome

The upgrade passed the full correctness gate: **109 tests passed, 0 failed,
1,193 assertions**. Both external-package compiled-Zod builds retained complete
compiler coverage with no fallbacks. The transform-free schemas remained
fast-path eligible.

The full speed ordering was identical to the Zod 4.3.6 session. The Zod-family
median comparison was:

| Zod path | 4.3.6 median | 4.4.3 median | Change |
| --- | ---: | ---: | ---: |
| Current Zod native transforms | 186.328 ms | 191.683 ms | **+2.9%** |
| Compiled Zod native transforms | 119.350 ms | 119.223 ms | -0.1% |
| Zod + shared manual normalizer | 135.176 ms | 137.448 ms | **+1.7%** |
| Compiled Zod + shared manual normalizer | 65.185 ms | 65.107 ms | -0.1% |

The interpreted Zod paths were higher, while both compiled paths reproduced
within 0.2%. This is not enough to claim a Zod-version regression. The sessions
were independent and not asserted idle, and non-Zod controls moved from 1.0%
lower to 1.4% higher between the same sessions.

## Measurement boundary

The primary timer began with an already parsed `unknown` value and ended after
the adapter returned normalized data or validation issues. It included alias
preparation, validation, and normalization. It excluded generation, file I/O,
`JSON.parse`, process and module startup, compiler builds, hashing, formatting,
and loopback HTTP work.

Each variant had ten fresh-process samples with a freshly parsed object graph.
Variant order rotated, all 100 samples were retained, and no outlier was
discarded.

```sh
bun run benchmark --profile diagnostic-10000 --seed 20260807 --rounds 10 --mode validator
```

## Synthetic and privacy boundary

The deterministic input contained 10,000 synthetic reports, 170,000 cells, and
49,149,405 encoded bytes under seed `20260807`. Every sample reported the same
input hash and returned 10,000 reports.

The isolated generated-profile privacy audit passed over the `smoke`, `small`,
and `diagnostic-10000` profiles: 10,101 reports, 1,036,655 keys, and 806,864
string leaves. No new input vocabulary or external dataset was introduced by
the Zod upgrade.

## Memory interpretation

Peak RSS is whole-process evidence, not a direct measurement of live validator
objects. The adjusted values in the opening table subtract aggregate medians;
they are not paired-sample deltas.

Every real-adapter median peak RSS was 0.9 to 3.3 MiB lower than in the Zod
4.3.6 session, including all non-Zod controls. This uniform shift should be
treated as session-level variation rather than a Zod-specific memory gain.

TypeBox, Valibot, and native-transform Valibot each had a discontinuous
high-memory sample. Complete raw samples remain necessary for stronger claims.
Fresh-process measurements do not predict garbage collection, throughput, or
tail latency in a long-lived process.

## Compiler evidence

- Native-transform compiled Zod optimized all nine intended exports with 100%
  coverage and no fallbacks; transform stages blocked fast-path eligibility.
- Compiled transform-free Zod optimized both request schemas at 48/48 nodes,
  100% coverage, fast-path eligible, with no fallbacks.
- The fully bundled artifact remained runtime-incompatible under Bun 1.3.14.
  The benchmark used the external-package artifact and never substituted
  interpreted Zod.

## Conclusion

The Zod 4.4.3 state is behaviorally compatible and preserves the earlier broad
performance ordering. Ajv, compiled transform-free Zod, and regular TypeBox
with shared normalization remain the leading diagnostic candidates.

The compiled Zod results reproduced closely. The interpreted Current Zod
median was 2.9% higher, which warrants a controlled multi-session version
comparison but does not establish a regression by itself.
